# MQ 项目面试问答预案

## Q1：为什么这个项目的性能 smoke 不用 JMeter？
- 项目使用自定义 TCP 协议和二进制序列化，Java 测试脚本可以直接复用现有客户端与服务端能力，比通用压测工具更贴近真实链路。
- 这轮目标是验证可执行基线和产出可解释指标，不是堆工具数量。

## Q2：这些测试用例是怎么设计出来的？
- 路由规则用等价类和负模式回归，重点卡住内联 wildcard 这种真实缺陷。
- GC 边界使用 2000 / 2001 与 50% 有效消息比例附近的边界值分析。
- 发布、消费、ACK 用状态转换和异常路径覆盖，补齐缺失 exchange、缺失消息、durable ACK 清理等场景。

## Q3：这套测试资产最大的风险还在哪里？
- 当前性能 smoke 主要用于验证基线和链路可用性，还不是工业级高并发极限压测。
- 覆盖率可以帮助发现盲区，但不能替代长时间稳定性、Broker 重启恢复和故障注入验证。

## Q4：你怎么保证这些结果是可信的？
- 所有盘点、覆盖率和正式报告都只读取白名单中的 Surefire、JaCoCo 和 perf 产物，避免历史残留文件混入统计。
- 数字全部来自真实执行输出，不手填成功率、不虚构性能数据。
